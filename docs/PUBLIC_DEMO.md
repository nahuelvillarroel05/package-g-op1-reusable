# Public synthetic MCP demonstration

This example uses the published engine and the real MCP Python SDK over stdio. No model, GGUF, Ornith server, commercial API or private source is required. It demonstrates the document-metadata-to-synthetic-totals pipeline; it does not execute an arbitrary command or qualify native operation.

Use Windows and Python 3.14. Start in a fresh disposable checkout with a short path; generated workspaces are single-use. From the repository root in PowerShell:

```powershell
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -r mcp/INSTALL_FREEZE.txt -r tests/requirements.txt
.venv\Scripts\python.exe -m pip check
.venv\Scripts\python.exe -I -c "import site, sys, jsonschema; from pathlib import Path; assert Path(jsonschema.__file__).resolve().is_relative_to(Path(sys.prefix).resolve()); p = Path(site.getusersitepackages()); p.mkdir(parents=True, exist_ok=True); print(p)"
.venv\Scripts\python.exe -B tools/verify_public_tree.py
.venv\Scripts\python.exe -B tests/smoke_stdio.py
```

The preparation command checks that JSON Schema loads from the isolated venv and creates the Python-derived user-site directory if missing, without installing anything there. The frozen runtime unconditionally validates that directory before enabling I4/I5 evidence; `-I` does not remove this existence check. An absent directory yields `PATH_NOT_FOUND`. This prerequisite does not waive engine path checks or change the original source.

The script is both the public demonstration and the integration check used by CI. It connects a real SDK client to `pg_i7_mcp.server`, initializes one fresh workspace, and performs these operations:

1. `tools/list` exposes exactly ten tools, including `inspect`, `run_pipeline`, `verify`, `query` and `recover`.
2. `prepare_document_selection` commits the public `sample.md` and `sample.json` fixture selection; `validate_document_selection` verifies it. `run_pipeline` executes the existing bounded pipeline once.
3. `synthetic_operation` prints the returned run reference, local evidence directory and actual evidence filenames. Inspect that directory under `runtime/campaigns/<fresh-workspace>/runs/` to see the generated bytes.
4. `verify` requires a `PASS` result from the engine's evidence verification.
5. `query` prints the actual `i4_semantic_graph_identity` response. Graph and prospective provenance are also queried and checked for tool errors.
6. `recover` reads the committed run and pipeline attempt. The script requires `PASS`, `dispatch=NOT_PERFORMED`, `redispatch=PROHIBITED`, `read_only=true` and replay rejection. It compares every workspace file's SHA-256 and membership before and after recovery, requiring no changes.

Finally it checks rejection of traversal, absent runs, type coercion and unexpected arguments. A failed assertion or tool error exits nonzero. `MCP_API_TIMINGS_V3.jsonl` contains measured server API timings; an existing timing file is preserved by refusing to overwrite it. Re-run in a new checkout, rather than deleting evidence or repeating a producer.

Successful output includes these records (identifiers, paths, evidence filenames, protocol versions and timings are generated, not fixed expected values):

```text
HANDSHAKE_OK
LIST_OK
{"step": "tools_available", "tools": [...ten actual tool names...]}
...
{"step": "verify", "status": "PASS"}
{"step": "query", "result": {...actual verified query response...}}
{"step": "recovery", "status": "PASS", "dispatch": "NOT_PERFORMED", "redispatch": "PROHIBITED", "workspace_file_hashes": "UNCHANGED", "replay_rejected": true}
```

The final record reports `pipeline_evidence_query_graph_provenance_recovery=PASS` and the negative-check result. These are synthetic, local consistency checks. File hashes and a successful demo do not establish independent custody, network confinement, authentic process ownership or formal operational qualification.

For the Python API, run `python -B examples/api_synthetic_pipeline.py` with the same environment. It prints `status=PASS`, the actual workspace/run directory and the five executed checks (`graph`, `provenance`, `query`, `recover`, `verify`).
