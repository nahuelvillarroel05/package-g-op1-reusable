# PGOP1 experiments

Start with [E1/E2/F engineering modes](ENGINEERING_MODES.md), [purpose](RUNS_PURPOSE.md), [policy](EXPERIMENTAL_POLICY.md), [compact future RUN template](RUN_TEMPLATE.md), [registry](RUN_REGISTRY.json), [publication policy](PUBLICATION_POLICY.md), [publication receipt](schemas/pgop1.experimental.run-publication.v1.md), and [receipt template](templates/RUN_PUBLICATION_RECEIPT_TEMPLATE.json).

Every RUN declares its mode. E1 supports experiments and recorded failures with minimum safety, integrity, provenance, and recovery controls; E2 validates specific properties; F retains formal qualification. These modes are not agent reasoning levels.

[RUN004](runs/run-004/README.md) prospectively adopts E1 under Owner decision `PGOP1_ENGINEERING_MODES_AND_RUN004_E1_001`; verified attempts and results determine actual execution status. The E1 profile does not retroactively approve rev004 or establish formal qualification.

RUN001/002/003 and pilots retain their historical lineage and scope by reference: [RUN001](runs/run-001/PUBLICATION_RECORD.json), [RUN002](runs/run-002/PUBLICATION_RECORD.json), and [RUN003](runs/run-003/PUBLICATION_RECORD.json). The [historical full contract template](RUN_CONTRACT_TEMPLATE.md) and [attempt template](ATTEMPT_CONTRACT_TEMPLATE.json) remain available in their applicable contexts. The full formal document package is not an E1 entry requirement.
