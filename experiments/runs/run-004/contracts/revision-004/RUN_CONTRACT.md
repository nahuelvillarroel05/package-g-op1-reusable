## Audit correction 001 — applicability, abstention accounting and receipt bytes

Applicability and availability are independent. Before execution, enumerate a candidate unit-predicate universe for every selected unit across the eight predicate families in the execution plan. Determine APPLICABLE, NOT_APPLICABLE or UNKNOWN_APPLICABILITY under versioned semantic domain rules, recording a reason for every excluded pair. Missing output, evidence, reference, producer binding, runtime or reserved evidence is NEVER a NOT_APPLICABLE reason for a semantically applicable predicate. UNKNOWN_APPLICABILITY stays in the conservative applicable denominator until qualified prospectively; report it separately. Freeze and reconcile universe = applicable + genuine not-applicable (unknown remains included in applicable), with exact unique pair sets and counts per family/predicate/audit type. Any truly out-of-domain predicate stays visible in the not-applicable ledger. All applicable pairs, including unavailable/blocked evidence, form the audit coverage denominator. The planned execution allocation cannot prune them. Report semantic-predicate coverage independently of structural/provenance coverage and show numerator, full applicable denominator, missing-evidence and not-applicable counts. The requirement is no reduction of semantic scope through allocation; an all-structural plan cannot claim overall semantic coverage.

For each actual abstention, the mutually exclusive justification partition is JUSTIFIED / UNJUSTIFIED / UNKNOWN_UNREVIEWABLE. JUSTIFIED requires observed failure of a frozen prerequisite bound to evidence; UNJUSTIFIED requires demonstrated satisfaction of all applicable frozen prerequisites plus a violated mandatory decision rule, with evidence and reviewer rationale. Insufficient review evidence or unsupported prerequisite assertions produce UNKNOWN_UNREVIEWABLE. Those three counts must reconcile exactly to the total actual abstentions in each identical unit/predicate partition. No undefined 'unsupported' bucket substitutes for UNJUSTIFIED. Justification review is not independent semantic truth.

Prospective receipt wire contract: immutable UTF-8 JSON payload bytes, no BOM, no trailing newline; sorted keys, compact separators (comma and colon), non-ASCII emitted as UTF-8, no duplicate keys, NaN/infinity or floats; integers/strings/booleans/null only, no Unicode normalization. SHA-256 is over the exact payload-file bytes; the receipt digest is detached in a separate envelope/index and is NOT a field inside the hashed payload. The unit payload includes parent_receipt_sha256 (null at genesis), immutable attempt identity, source/contract/config binding and sequence. A checkpoint payload uses the same encoding and detached digest rule; includes parent_checkpoint_sha256 (null at genesis), ordered immutable receipt payload hashes, exact completed/pending/inflight unique sets and binding hashes. Receipt payloads do not point forward to the checkpoint, avoiding cycles. Verification must compare raw bytes/hash, enforce canonical reserialization equality and schema, follow parent/sequence ownership, reject duplicates or changed bindings, and reconcile selected = completed + pending + inflight as disjoint sets. Only actual start+terminal processing receipts with valid checkpoint membership count complete; missing/ambiguous evidence of attempt durability is incomplete/BLOCKED. The execution-readiness audit must qualify an implementation of this rule; this documentary definition is not a claim that a writer/validator was implemented or run.
